# Dashboard token usage — Claude Code

## 🇬🇧 English

A local HTML dashboard showing the costs and tokens consumed with Claude Code,
generated by a suite of Python hooks that read the logs Claude Code already
writes to `~/.claude/logs`. No data leaves your PC and no external API calls
are made: everything is computed and rendered locally.

### Installation

**Download a single file and double-click it.** No Python needed, no need to
clone the repo, and no need to come back here when a new version is released:
the application updates itself.

| System | File to download from the [Releases](https://github.com/Maitanluca1996/dashboard-token/releases/latest) |
|---|---|
| Windows | `dashboard-token-windows.exe` |
| macOS | `dashboard-token-macos` |
| Linux | `dashboard-token-linux` |

When it finishes, restart Claude Code if it was open (the hooks take effect
from the next session). At the end of the first turn you will find the
dashboard at `~/.claude/dashboard-token/dashboard.html`.

> **Note**: the generated pages and the installer messages are in Italian.

> **The system will warn you on first launch.** The binaries are not signed
> with a code signing certificate. On Windows, SmartScreen appears: "More
> info" → "Run anyway". On macOS: right-click the file → "Open". On Linux:
> `chmod +x dashboard-token-linux` before launching it.

#### Updates

No action required. The application checks once a day whether a newer release
exists and, if it finds one, updates itself in the background, verifying the
SHA-256 checksum of what it downloads. The check does not slow down Claude
Code turns: it runs in a detached process.

To **force the check right away** instead of waiting, just double-click the
installed application:

    ~/.claude/hooks/dashboard-token/dashboard-token

It shows the current version, checks, and if it finds something new it asks
for confirmation before proceeding. There is no button inside the dashboard
because that is an HTML page opened in the browser, and a browser cannot
launch a local executable.

#### Optional customizations

There is no configuration wizard, because there is nothing to configure: all
paths are derived at runtime from the user's home directory. If you want,
though, you can run from a terminal:

```bash
~/.claude/hooks/dashboard-token/dashboard-token config
```

to move the output folder, choose the language of the terminal messages, or
give a readable label to your Claude accounts (only useful with multiple
accounts on the same PC).

### Language

The pages are available in Italian and English, with a switch in the header
next to the update time. On a first visit the browser's language decides;
after that the choice is remembered, and it holds across the three pages.

The terminal messages follow their own chain, because a terminal has no
switch: the `DASHBOARD_TOKEN_LANG` environment variable (`it` or `en`) for a
single command, otherwise a `"lang"` key in `dashboard_config.json` for this
machine once and for all, otherwise the operating system's language, and
English as the last resort.

```bash
DASHBOARD_TOKEN_LANG=en dashboard-token backfill
```

Adding a language means writing one `lang_xx.py` beside `lang_it.py` and
naming it in the registry at the top of `i18n.py`. The markup, the
JavaScript and the number formatters do not change, and the switch grows on
its own because it is built by walking that registry. The cost guide is the
exception: it is long prose and lives as one template file per language.

### How it works

Claude Code's `Stop` and `PostToolUse` hooks record tokens and operations in
CSV files (`~/.claude/logs`); at the end of each turn the
`generate_dashboard/` package regenerates in-process the three self-contained
HTML pages (inline CSS/JS). For the full architectural details see
[NOTES.md](NOTES.md).

#### Why distribution is two-stage

The file you download is an **installer** in "onefile" form, which carries the
**application** in "onedir" form inside it and extracts the latter into
`~/.claude/hooks/dashboard-token/`.

The complication has a measured reason. A onefile binary unpacks itself into a
temporary folder on every launch, which costs ~880 ms; the `PostToolUse` hook
fires on **every** tool call, so that cost would multiply across the whole
turn. In onedir form, startup takes ~225 ms, in line with the Python-script
installation (~320 ms). The onefile installer pays that cost only once, at
install time, where it does not matter.

| Form | Startup | Role |
|---|---|---|
| onefile | ~880 ms | installer: you download it and launch it once |
| onedir | ~225 ms | application: launched by Claude Code on every turn |

### Development

The canonical hook sources live in `~/.claude/hooks/` and are mirrored into
`installer/hooks/` (see `installer/sync-from-live.ps1`); it is from that copy
that CI builds the binaries.

```bash
python packaging/test_setup_hooks.py
```

runs the tests for the `settings.json` merge (the part that touches a user
file, and the only one where an error would be silent). To build the binaries
locally you need the two stages in order:

```bash
pyinstaller --clean --noconfirm --distpath dist/app --workpath build/app packaging/app.spec
```

```bash
pyinstaller --clean --noconfirm --distpath dist --workpath build/installer packaging/installer.spec
```

## 🇮🇹 Italiano

Dashboard HTML locale che mostra costi e token consumati con Claude Code,
generata da una suite di hook Python che legge i log già scritti da Claude
Code in `~/.claude/logs`. Nessun dato lascia il tuo PC e non vengono
effettuate chiamate API esterne: tutto è calcolato e renderizzato in locale.

### Installazione

**Scarica un file solo e fai doppio click.** Non serve Python, non serve
clonare la repo, e non serve tornare qui quando esce una versione nuova:
l'applicazione si aggiorna da sola.

| Sistema | File da scaricare dalle [Release](https://github.com/Maitanluca1996/dashboard-token/releases/latest) |
|---|---|
| Windows | `dashboard-token-windows.exe` |
| macOS | `dashboard-token-macos` |
| Linux | `dashboard-token-linux` |

Al termine, riavvia Claude Code se era aperto (gli hook si attivano dalla
sessione successiva). Alla fine del primo turno trovi la dashboard in
`~/.claude/dashboard-token/dashboard.html`.

> **Al primo avvio il sistema ti avvisa.** I binari non sono firmati con un
> certificato di code signing. Su Windows compare SmartScreen: "Ulteriori
> informazioni" → "Esegui comunque". Su macOS: tasto destro sul file → "Apri".
> Su Linux: `chmod +x dashboard-token-linux` prima di lanciarlo.

#### Aggiornamenti

Nessuna azione richiesta. L'applicazione controlla una volta al giorno se
esiste una release più recente e, se la trova, si aggiorna in background
verificando il checksum SHA-256 di quello che scarica. Il controllo non
rallenta i turni di Claude Code: gira in un processo staccato.

Per **forzare il controllo subito** invece di aspettare, basta un doppio
click sull'applicazione installata:

    ~/.claude/hooks/dashboard-token/dashboard-token

Mostra la versione attuale, controlla, e se trova qualcosa di nuovo chiede
conferma prima di procedere. Non esiste un pulsante dentro la dashboard
perché quella è una pagina HTML aperta nel browser, e un browser non può
lanciare un eseguibile locale.

#### Personalizzazioni facoltative

Non c'è nessun wizard di configurazione, perché non c'è niente da
configurare: tutti i percorsi si ricavano a runtime dalla home dell'utente.
Chi vuole può però lanciare da terminale:

```bash
~/.claude/hooks/dashboard-token/dashboard-token config
```

per spostare la cartella di output, scegliere la lingua dei messaggi a
terminale o dare un'etichetta leggibile ai propri account Claude (utile solo
con più account sullo stesso PC).

### Lingua

Le pagine esistono in italiano e in inglese, con uno switch nell'intestazione
accanto all'ora di aggiornamento. Alla prima visita decide la lingua del
browser; da lì in poi la scelta viene ricordata, e vale per tutte e tre le
pagine.

I messaggi a terminale seguono una catena propria, perché un terminale non ha
uno switch: la variabile d'ambiente `DASHBOARD_TOKEN_LANG` (`it` oppure `en`)
per un singolo comando, altrimenti una chiave `"lang"` in
`dashboard_config.json` per questa macchina una volta per sempre, altrimenti
la lingua del sistema operativo, e l'inglese come ultima spiaggia.

```bash
DASHBOARD_TOKEN_LANG=en dashboard-token backfill
```

Aggiungere una lingua significa scrivere un `lang_xx.py` accanto a
`lang_it.py` e nominarlo nel registro in cima a `i18n.py`. Il markup, il
JavaScript e i formattatori di numeri non cambiano, e lo switch cresce da
solo perché è costruito scorrendo quel registro. La guida ai costi è
l'eccezione: è prosa lunga e vive in un file template per lingua.

### Come funziona

Gli hook `Stop` e `PostToolUse` di Claude Code registrano token e operazioni
in CSV (`~/.claude/logs`); a ogni fine turno il package `generate_dashboard/`
rigenera in-process le tre pagine HTML self-contained (CSS/JS inline). Per i
dettagli architetturali completi vedi [NOTES.md](NOTES.md).

#### Perché la distribuzione è a due stadi

Il file che scarichi è un **installer** in forma "onefile", che si porta
dentro l'**applicazione** in forma "onedir" ed estrae quest'ultima in
`~/.claude/hooks/dashboard-token/`.

La complicazione ha una ragione misurata. Un binario onefile si scompatta in
una cartella temporanea a ogni avvio, il che costa ~880 ms; l'hook
`PostToolUse` scatta a **ogni** chiamata di strumento, quindi quel costo si
moltiplicherebbe per tutto il turno. In forma onedir l'avvio è ~225 ms, in
linea con l'installazione a script Python (~320 ms). L'installer onefile
paga il costo una volta sola, all'installazione, dove non conta.

| Forma | Avvio | Ruolo |
|---|---|---|
| onefile | ~880 ms | installer: lo scarichi e lo lanci una volta |
| onedir | ~225 ms | applicazione: la lancia Claude Code a ogni turno |

### Sviluppo

I sorgenti canonici degli hook vivono in `~/.claude/hooks/` e vengono
rispecchiati in `installer/hooks/` (vedi `installer/sync-from-live.ps1`); è
da quella copia che la CI costruisce i binari.

```bash
python packaging/test_setup_hooks.py
```

esegue i test del merge di `settings.json` (la parte che tocca un file
dell'utente, e l'unica dove un errore sarebbe silenzioso). Per costruire i
binari in locale servono i due stadi in ordine:

```bash
pyinstaller --clean --noconfirm --distpath dist/app --workpath build/app packaging/app.spec
```

```bash
pyinstaller --clean --noconfirm --distpath dist --workpath build/installer packaging/installer.spec
```
